# 文章表現ガイド（旧ブログの文体観察）

オーナーが個人で書いていた技術ブログ `akatak.hatenadiary.jp` の文章表現を観察し、
記事生成で再現できる形にまとめたもの。

## このドキュメントの位置づけ

- **散文の書き方だけを扱う。** 記事の事実・構成・禁止事項は、常にブリーフが優先する。
  ブリーフが節構成を指定していれば、そちらに従う。ここに書いた癖は文の書き方にだけ適用する。
- テンプレート（`src/templates/*.py`）の `style_guide` は1行の指針しか持たない。
  それを置き換えるものではなく、より細かい粒度で補うもの。

## 出典と精度（重要）

- 調査日: 2026-09-11
- 調査方法: 書き込み系ツールを持たない `web-researcher` サブエージェントに `WebFetch` で読ませた
- 読んだ記事: 8本（2018〜2022年）。エッセイ1本、体験記1本、技術記事6本
- **数値はすべて小型モデルによる概算で、原文を機械的に数えたものではない。**
  原文をそのまま確認できたのは1記事の冒頭3段落のみ。回数・文字数は誤差を含む
- 取得結果に矛盾があり**採用しなかった観察**: 一部記事の「だ・である調が混在」（同じ取得の
  段落一覧では全文末がです・ます系だった）、「ハマった／詰まった」という語彙（後追いで
  該当箇所を確認できず、こちらが例示した語が返ってきた可能性が高い）
- 2019年以前のシリーズ記事は未読。2021年の絵文字、2022年の太字は各1本のみの事例で、
  年代変化かジャンル差かを判断できていない

## 観察された傾向（技術記事）

1. **全文です・ます調。** だ・である調は見出しと箇条書き項目にだけ現れる
2. **一文は45字前後。** 30〜60字のレンジ。短文の畳みかけはしない
3. **1段落は1〜2文。1文だけの段落が全体の半分近くを占める。** 3文以上の段落は少数派
4. **一人称を出さない。** 技術記事では「私」が0〜2回。必要なときは「自分」「自分自身」を
   副詞的に使う。「私」を主語に立てるのは体験記のとき
5. **読者を「あなた」と呼ばない。** 全記事で0回。手順は「〜していきます」「〜みましょう」と
   一緒に進む形で書く。「〜してください」は避ける
6. **太字を使わない。** 8本中7本で0箇所。強調したい用語・ファイル名・書名は
   **カギカッコ「」で受ける**（1記事あたり15〜27箇所と多用する）
7. **コードの直前に1〜2文の予告を置く。** 「次に、〜します」の形。
   コードの後に長い解説を足す型ではない
8. **見出しは動詞終止形か体言止め。** 手順記事なら番号を振る。疑問形の見出しはエッセイのみ
9. **冒頭は結論から入らない。** 挨拶・時候／動機や不満／前回の続編宣言のいずれかで、
   2〜3段落かけて助走する。確認した8本に結論から入る記事は無かった
10. **「まとめ」「終わりに」節を置かない。** 次回予告の1文、リンクの案内、
    「ご参考になれば幸いです」型の献辞のいずれかで終わる
11. **つまずきは書くが、嘆かない。** 「うまくいきませんでした」「諦めました」程度の語彙。
    自嘲もスラングも使わない。「こうならなかった、ではこうする」と次の手に繋げる
12. **段落頭の接続詞が定型化している。** 「さて、」「なお、」「ただし、」「ただ、」「また、」
    「そこで、」「まずは、」。補足は「なお、」で後置する
13. **英単語・ライブラリ名は訳さずそのまま地の文に混ぜる。** カタカナ語も多い
14. **括弧書きで小声の補足を添える。** 感想や自問を（〜なのでしょうか？）の形で入れる
15. **箇条書きは列挙が本質のときだけ。** 技術記事では0ブロックのものが複数あった。
    使う場合、項目は単語ではなく文にする。表はほぼ使わない

### 体験記・エッセイを書くときの差分

一文を80〜150字まで伸ばす／「私」を主語として多用する／「〜と思います」「〜でしょう」を増やす／
疑問形の見出しを使う／箇条書きで理由を並べる。

## オーナーの上書き（旧ブログの観察より優先する）

2026-09-11 にオーナーから受けた指示。**観察された癖と衝突する場合、こちらが勝つ。**

- **太字は使う。** 旧ブログは太字をほぼ使わないが、読みやすさを優先して要点は太字にする。
  上の項目6（太字を使わない）は採用しない。カギカッコは用語・ファイル名・引用に使う
- **結論から先に書いてよい。** 旧ブログは8本すべてが助走から入るが、文脈に応じて使い分ける。
  結論が先にあったほうが読みやすい記事では、冒頭で主張を出す。
  上の項目9（冒頭は結論から入らない）は「そういう型もある」程度に読む
- **「正直に言うと」を使わない。** Claude の癖として目につくため。
  うまくいかなかったことは書くが、この前置きを付けずに事実から入る
- **細かく書きすぎない。** 事例を網羅すると読みにくい。列挙は削って、要点だけ残す
- **「で、結局どうだったのか」を書く。** 起きたことの列挙より、読者が知りたいのは結果と評価。
  やったことを並べるだけで終わらせず、**効果があったのかどうかを明示して締める**
- **不具合や指摘の逐一の説明は、それ自体では読者の関心事ではない。**
  個々の事例より、そこから言えることを書く

## 使うときの注意

- **口癖を盛らない。** 「〜ですね」「んですよね」は各記事に1回程度しか出ない。
  「させていただきました」のような過剰な丁寧語は観察された癖ではあるが、
  真似すると模倣に見える。多くても1〜2回にとどめる
- **時候の挨拶は個人ブログの型。** 会社としての発信では使わない
- ブリーフが表や箇条書きを内容として渡してきた場合は、
  この文体（表をほぼ使わない）より**ブリーフを優先する**
